## Найдена ошибка назначения CRM — главный незавершённый пункт

В 13:06:59 МСК пользователь отправил мобильный тест из формы ИФНС с
`utm_source=owner_qa`. Сервер принял его; CRM вернула `sent`, сделка `46570903`.
Однако это **старый** аккаунт `rahimaconsulting.amocrm.ru`, воронка «Отдел
продаж», этап «Новый запрос», ответственный Виктор. Пользователь показал
сделку и уведомление SalesBot на скриншоте, затем уточнил, что компания уже
работает в **`presentationrc.amocrm.ru`**. Успех API не означал доставку в
актуальный аккаунт. Первоначальный вывод о полном успехе исправлен.

На сервере в `/etc/dokumenty82-form.env` оставались старый домен и OAuth.
Воронка/этап/ответственный явно не задавались, использовались значения CRM
по умолчанию. Это реальный дефект подключения, но не доказательство, что
в сентябре было много потерянных заявок: до этого QA в серверном журнале
не было ни одной сентябрьской заявки. Проверять факты отдельно от гипотез.

Выполнено временное переключение без отправки в старый аккаунт:

- `AMO_SUBDOMAIN=presentationrc.amocrm.ru`;
- новый отдельный `AMO_TOKEN_PATH=/var/lib/dokumenty82-leads/amo-presentationrc-oauth-token.json`;
- старые bearer/client credentials и старые ID полей/воронки/этапа/пользователя
  исключены из текущего окружения; новый токен ещё не получен;
- `D82_ACCEPT_LOCAL_ONLY=1`: заявки сохраняются на сервере со статусом
  `stored_only`, в старую amoCRM не отправляются;
- обновлён секрет состояния подключения; он не печатался и не попадал в Git;
- сервис перезапущен, health OK. Проверено, что старого токена нет в активном
  подключении, а создание возвращает `stored_only` без сетевой отправки.

Защищённая резервная копия прежней конфигурации:
`/root/codex-conversion-20260911/form-env-before-crm-migration` (0600).
Старый OAuth-файл сохранён отдельно для восстановления/проверки истории;
не включать его обратно в рабочую отправку.

Chrome (браузер 3) вошёл в Presentation как Виктор; номер аккаунта в UI
`32965862`. Настройки интеграций не отображаются; открытие раздела возвращает
на рабочий стол. Пользователю задан запрос войти администратором в Chrome.
Это недостающий доступ, а не повторное согласование уже разрешённой миграции.
IAB не открывает новую amoCRM по сети, Chrome открывает — использовать Chrome.

Позже пользователь попросил исключения Throne, чтобы агент продолжил сам.
Ему даны строки для поля «Напрямую»: `suffix:amocrm.ru`,

После применения проверить IAB и доступ администратора; не считать сетевое

через этот API — нужен совместимый вариант или частная интеграция, затем тест.
