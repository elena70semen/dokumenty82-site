# Ручная передача полученных заявок Presentation в Метрику

Работает через существующее серверное OAuth-подключение сайта к Presentation.
Новый вход администратора amoCRM для этой выгрузки не нужен. Это утилита для
ручного запуска, не автоматическая синхронизация и не замена импорта стадий Albato.

- Исходник: `server/export_metrika_crm.py`. SHA256 установленной версии:

  `/var/lib/dokumenty82-leads/metrika-export-20260914-final/manifest.json`.
  Пригодных строк **0**, `uploaded=false`. CSV при нулевом результате не создаётся.

## Что считается событием

Только запись формы сайта после перехода в Presentation, с `crm.status=sent`,
ClientID или YCLID и соответствующей живой сделкой в аккаунте `32965862`.
У сделки проверяются ID, account_id, дата создания и тег `site`.
Событие датируется временем создания сделки, а не временем экспорта.

Исключаются `owner_qa`, тестовая среда, явный тест в начале имени/сообщения/темы,
QA-теги CRM, неподтверждённая доставка, отсутствие атрибуции, записи до миграции,
будущие даты и записи старше 21 дня. Дубликаты одной сделки внутри выгрузки
исключаются. Ошибка API останавливает экспорт; частичная выгрузка не публикуется.

CSV не содержит телефона, имени, email, текста заявки, цены или выручки.
Файлы имеют права 0600, каталог 0700. ClientID/YCLID также не следует помещать
в публичные отчёты или Git. Не складывать эту цель с `lead_submit_success`:
две цели описывают этапы одной заявки, а не два разных лида.

## Запуск на VPS

Использовать SSH и имеющийся ключ. На VPS выполнить как root, подставив новое
имя каталога. Процесс получает окружение действующего приёмника без печати
секретов; сам приёмник перезапускать не требуется.

```python
import os, runpy, subprocess, sys
from pathlib import Path

pid = subprocess.check_output(
    ['systemctl', 'show', 'dokumenty82-lead', '-p', 'MainPID', '--value'],
    text=True).strip()
for item in Path('/proc/' + pid + '/environ').read_bytes().split(b'\0'):
    if b'=' in item:
        key, value = item.split(b'=', 1)
        os.environ[key.decode()] = value.decode()

sys.argv = [
    '/opt/dokumenty82-form/export_metrika_crm.py',
    '--output-dir', '/var/lib/dokumenty82-leads/metrika-export-NEW-RUN',
]
# Для всех ранее принятых Метрикой выгрузок добавлять повторяемый аргумент:
# sys.argv += ['--uploaded-manifest', '/private/accepted-export/manifest.json']
runpy.run_path(sys.argv[0], run_name='__main__')
```

Каталог должен быть новым; утилита не перезаписывает старую выгрузку.
По умолчанию окно ограничено последними 21 днями. Отсутствующий ClientID
не подменяется выдуманным: при валидном YCLID используется отдельный файл.

## Загрузка в Метрику

1. Проверить счётчик и созданную цель. В разделе Настройка → Загрузка данных →
   Загрузка офлайн-конверсий выбрать файл.
2. `conversions-clientid.csv` загружать с типом привязки ClientID;
   `conversions-yclid.csv` — отдельно с типом YCLID. Пустые файлы не создаются.
   Колонки: выбранный идентификатор, `Target`, `DateTime` (Unix timestamp).
3. Проверить результат обработки и привязки в отчёте «Офлайн-конверсии».
   Созданный файл или HTTP-ответ не равны подтверждённой атрибуции.
4. Только когда **все файлы данной выгрузки** приняты, использовать её manifest
   в последующих запусках через `--uploaded-manifest`. Скрипт сам не отмечает
   данные отправленными. Не передавать manifest непринятого или частично
   загруженного экспорта, иначе оставшиеся строки будут исключены.

При восстановлении штатного Albato-коннектора сначала решить, какой поток
используется для каких событий. Не импортировать те же данные повторно как
новые уникальные обращения. Для квалификации и оплаты нужны отдельные правила
по реальным этапам, а не предположение «сделка создана = продажа».

Источники: [формат и цель офлайн-конверсий](https://yandex.ru/dev/metrika/ru/management/offline-conv),
[ручная загрузка и проверка привязки](https://www.yandex.ru/support/metrica/ru/data/offline-conversion-data).
